From 39 warnings to 10 in one day

GitHub keeps a list of known weak spots in the building blocks the app uses. This morning it showed 39. Tonight it shows 10. None of the 10 are in the part of the app you install.

The idea in one picture

The app is a house built from other people's bricks

Bricks

Video Forge is built from about 800 free parts made by other people. One draws the window, one reads web addresses, one turns style sheets into a page. We call them packages.

Cracks

Sometimes someone finds a crack in a brick, and the brick maker sends out a fixed one. GitHub watches our list of bricks and raises a warning for every brick with a known crack.

Swapping bricks

Today we swapped the cracked bricks for fixed ones of the same shape, so nothing else in the house had to move.

Fresh, not wet

We only used bricks that had been out for at least a week. A brick made this morning might have its own new crack that nobody has spotted yet.

What changed

Six changes you'd actually feel the benefit of

The app's window and engine

Electron, the part that draws the window and runs everything. It got the maker's latest small safety repair, including protection against a set of stolen internet ID cards.

ships in the app1 serious warning gone

The web-address checker

A small part that reads addresses like https://… inside the video builder. Tricky addresses could fool it into reading the wrong place. That's the biggest single clean-up today.

ships in the app11 warnings gone

The data checker

Zod checks that data has the right shape before the video builder uses it. Very large data could make it eat all the memory. Remotion, the video builder, still asks for the old one, so we told it to use the fixed one anyway.

ships in the app1 serious warning gone

The style-sheet tools

Four small parts that turn colours and layouts into a finished page. Some odd inputs could make them spin for a very long time and freeze. Now they don't.

ships in the app5 warnings gone

The installer-making tools

Parts we only use to build the setup file: a downloader and a file-name matcher. They never reach your computer as part of the app, but now they're clean too.

build tools only12 warnings gone

A weekly check-up

New today. Once a week, GitHub opens one tidy list of updates for us to look over, so warnings don't pile up to 39 again. This one changes no app code.

Still open

Why we didn't fix the last 10

The short version: these 10 cracks are in the scaffolding we use while building, not in the house you live in. The only fixed bricks for them are a new, bigger shape that doesn't fit the old holes. Swapping them means rebuilding part of the scaffolding, and we'd rather do that on purpose, on a quiet day, than in a rush.
8

Vite, the "preview while I build" tool

It shows the app live while it's being worked on. It isn't part of the app you install. The fix only exists in Vite 6, a new generation. Vite 6 also needs a newer electron-vite, the tool that builds the app, so the build setup changes. That could stop "start the app" or "build the installer" from working until it's adjusted.

1

esbuild, inside Vite

An older copy that comes bundled with Vite 5. It disappears by itself when Vite is upgraded.

1

minimatch, a file-name matcher

Reported today. Only the installer-making tools use it. The only fixed version is a new generation, and it's just hours old, which is too fresh to trust yet.

Risk while they wait: low. Someone would need to already be on your computer, or tricking the developer preview, to use any of these. A normal person using the installed app never touches these parts.
